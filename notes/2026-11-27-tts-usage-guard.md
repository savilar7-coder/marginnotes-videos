# Narration usage guard — November 27, The Eye

Sergio requested verified waste fixes and less duplication. The old workflow generated every missing narration on any scripts push. This change requires an explicit manual approval for one script and its repository storage, plus a positive character ceiling. The selected branch is refreshed under one non-cancelling TTS concurrency group; only the selected MP3/alignment are staged. Voice/model/header conventions remain unchanged. Existing valid audio is reused, not generated again.

Offline checks: python -B -X utf8 -m unittest discover -s tests -p test_tts_workflow.py -v. Fourteen tests exercise the embedded workflow Python; HTTP, ffprobe and symlink checks use fixtures/mocks. Git workflow checks are structural; no hosted workflow was run.

Prepared in an isolated codex branch. No paid generation, live workflow execution, main change or public push. Owning-room review and Sergio publication approval are still required before adoption. ffprobe must be installed on the runner; its absence fails before a request. Other workflows/callers do not share this lock. A provider timeout or output push failure requires explicit recovery before another approved run; no guaranteed monetary saving is claimed.

Legacy-branch deployment guard: disable workflow ID 387061232 repository-wide before promotion; do not cancel existing runs. Maintain only `.github/workflows/tts-manual.yml`, displayed as `Narration (manual approval only)`, and keep the old workflow disabled. After merge, verify the manual path has a distinct workflow ID, only `workflow_dispatch`, and the legacy ID remains `disabled_manually`; do not re-enable the legacy ID. The manual guard preserves the original narration defaults and narrow output commit. No generation is needed to verify adoption.
